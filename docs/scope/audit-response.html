Two corrections to the report

H-3 · the suggested fix does not close it

Adding abci_query to the RPC deny list closes one of the two forms it arrives in

The finding is right and we reproduced it. The remedy is not. The deny list in yamale-api.conf is an nginx location regex — it matches on the URL path, and the JSON-RPC form carries the method in the POST body: 

POST /api/rpc/  {"method":"abci_query","params":{"path":"/blockchain.paymsg.v1.Query/Params"}}
  → code 0, value "CgA="        # the path regex never sees the method

So the entry would close GET /api/rpc/abci_query?path=… and leave the form every CosmJS client actually uses wide open. Worse, the clients depend on it: clients/rwa/src/abci.ts reads land and paymsg this way, which are two of the three modules the gate claims to close. A path-parameter allow-list has the same defect.

What we did instead. Treated the disclosure half as the decision it is. x/land is open in the repo with the argument written into the config — a title register nobody can inspect is not a title register, and the data was reachable regardless. That also settles F-6. Payment records and x/netting stay closed, and the config states plainly that closing them there does not close them. Neither is deployed.

Your reply then made this worse, and you were right about that too. See the section below: the deny list has never blocked anything either, so this is no longer a disclosure question with a payment-shaped deadline. It is now closed in the tree by a filter that parses the JSON-RPC envelope, and the deadline is “now”.

Two findings from your reply

Accepted · the RPC deny list has never blocked anything

Not “the fix would not have worked” — the rule already there does not work either

Confirmed against the funnel, every entry in the existing list:

MethodGET /api/rpc/<m>POST with {"method":"<m>"}
net_info403peer node id, moniker, listen addr, remote ip
dump_consensus_state403full round state
unconfirmed_txs403the mempool
broadcast_tx_commit403accepted, holds the connection

So every argument written into that rule — the mempool being everything needed to front-run a payment, dump_consensus_state serialising unbounded state per call, broadcast_tx_commit exhausting the connection pool — has been true and unmitigated for as long as the rule has existed.

One correction in your favour's opposite direction, because the severity should be right. The address net_info discloses is 100.117.244.96 — Tailscale CGNAT, not globally routable. Your phrasing, and the comment in our own config, say this is “the validator's real network location, which is the one thing the tunnel exists to hide”. It is not: what leaks is tailnet topology, node ids and monikers. The serious three are the denial-of-service and mempool methods, not the address.

Closed in the tree, not deployed. tools/rpcgate is an allow-list filter that parses the JSON-RPC envelope and applies one decision whichever way the method arrives, including inside a batch — a batch with an allowed call in front of a denied one is the obvious way past anything that reads only the first element. Eleven tests; 44 assertions fail against a permissive gate, which is the state of the host today. An allow-list rather than a deny list, so a CometBFT upgrade that adds a method cannot quietly widen the surface. The websocket is closed rather than proxied, because frames arrive after the upgrade and the gate cannot see into them — nothing here subscribes.

One defect you did not report

Found while building the vault ledger for C-2, in the code path immediately beside it.

x/tokenisation · keeper/sale.go · funds stranded

A dispute bond went into the shared module account and no message ever brought it back

DisputeSale takes dispute_bond_bps of the reported price from the challenger into the module account. ResolveDispute does not touch it, and neither does anything else — the bond is not recorded against the challenger, so nothing could return it even if it wanted to. A bond nobody can lose is not a deterrent; a bond nobody can recover is a fee for objecting. Same family as your M-4 and L-4.

The report now records the challenger and the bond. It returns to the challenger when governance corrects the price, and forfeits to the vehicle's holders when the figure stands — forfeits whole, not through holder_share_bps, because a penalty for delaying the holders is not income from the asset and the sponsor was not the one kept waiting.

What is still open, in the order you gave

Nothing below has been executed. Each item needs a key we should not use or a vote the owner has to cast, and the full commands sit in docs/scope/audit-remediation.md alongside the decisions each one forces. The order changed in this revision: the two items from your reply go first, because both are rotations rather than judgements.

  1. Rotate the key that holds the franchise (new) New feeder key in a file keyring, then move the 65,000 YML delegation off alice — redelegating leaves the franchise with the same key. Treat it as compromised: it has been readable by anyone with a shell on that box for the life of the chain.
  2. Deploy the RPC method gate (new, H-3) Built and tested; needs a binary, a unit file and one include replacing the deny-list regex on both hosts. The deploy script probes the POST form afterwards, so a half-finished install reports itself.
  3. Deal with the outstanding rewards (C-3) Withdraw, then burn, bond, or move to the 3-of-5 foundation group. Below the two above only because they are rotations and this is a judgement — the exposure here is larger, the exposure above is already realised.
  4. Rotate the other treasury admin (H-4) Treasury 2, "Lagos Field Operations", administered by the pi-2 feeder key.
  5. Appoint an ombudsman and extend the seizure cap (M-1, M-2) One governance proposal, built from the current params rather than written fresh — MsgUpdateParams replaces the whole set and several of these zeros are divisors.
  6. Declare the founding validator set (H-5a) No delay, and it is the half that makes the ceilings apply to anybody. Declaring the beneficial owners honestly is the difference between a concentration ceiling and a form.
  7. Start the constitutional amendment (H-5b) 9.2 days minimum whenever it starts, so it should start early. What to set the ceilings to depends on the declarations above — a ceiling that bites before the set can absorb it is worse than none.
  8. Include the security headers on both hosts (M-10) One include line per server block. The file and the check are already shipped.
  9. Decide on abci_query reaching closed modules (H-3, F-1) The remaining half, and a disclosure decision rather than a bug: the method gate does not itself stop abci_query reading a module that is 401 on REST. A path allow-list would. Free today; not free the day a participant is approved.
